## 2026-09-10 — ทิศทางกลยุทธ์: SMC

ผู้ใช้กำลังศึกษา **Smart Money Concepts (SMC)** และต้องการใช้เป็นฐานของระบบ

**ตัดสินใจ: ใช้ SMC เป็นกรอบตั้งสมมติฐาน แต่ทุกองค์ประกอบต้องนิยามเป็นตัวเลขและถูก
backtest จริง — ไม่รับมาใช้เพราะความนิยม**

ลำดับความสำคัญขององค์ประกอบ SMC (เรียงตามความ "เข้ารหัสได้" และมีเหตุผลเชิงกลไกรองรับ):

| องค์ประกอบ | เข้ารหัสได้ | เหตุผลเชิงกลไก | ลำดับ |
|---|---|---|---|
| Liquidity sweep (กวาด stop เหนือ/ใต้ high-low เดิม) | สูง | stop กระจุกที่จุดชัดเจนจริง | **1** |
| Break of structure / CHoCH | สูง | นิยามได้ด้วยกฎ swing point | **2** |
| Fair Value Gap (imbalance 3 แท่ง) | สูง | นิยามชัด ทดสอบ gap-fill ได้ | **3** |
| Premium / Discount (50% ของ range) | สูงมาก | นิยามเป็นเลขล้วน | 4 |
| Order block | ปานกลาง | นิยามกำกวม คนละคนตีคนละแบบ | 5 |
| Inducement / mitigation | ต่ำ | discretionary สูงมาก | ไม่ทำ |

**หมายเหตุสำคัญ:** จุดอ่อนที่สุดของ SMC คือความกำกวม — เทรดเดอร์ SMC 10 คนมองกราฟ
เดียวกันจะตี order block คนละที่ การเขียนเป็นโค้ดบังคับให้ต้องนิยามให้ชัด ซึ่งเป็น
ข้อดีของโปรเจกต์นี้ แต่ก็แปลว่า "SMC เวอร์ชันเรา" จะไม่เหมือน SMC ในคลิปที่ดูมา

## 2026-09-10 — Design brief ของ EA

- TP $12–25, SL $6–12 (RR ~1.7–2.0)
- ถือ 1–6 ชั่วโมง อาจข้ามคืน → **ต้องใส่ swap ใน backtest**
- คาดหวัง 1–3 ไม้/วัน — เกิดจากความเข้มงวดของเกณฑ์ ไม่ใช่จากโควตา
- ทุกไม้ตั้ง SL + TP ตั้งแต่วินาทีที่เข้า ไม่มีข้อยกเว้น
- ห้ามปิดมือ/ปิดก่อนกำหนด เว้นแต่เป็นกฎที่เขียนไว้ล่วงหน้า
- Daily loss limit เป็น **circuit breaker** (กันตลาดผิดปกติ/บั๊ก) ไม่ใช่การจำกัดพฤติกรรม
- พารามิเตอร์ปรับได้ < 10 ตัว

**ยกเลิกจากดีไซน์เดิม:** จำกัดไม้/วัน และ cooldown หลังขาดทุน
เหตุผล: เป็นการรักษาปลายเหตุของการเทรดไร้แผน ถ้าเกณฑ์เข้าเข้มงวดพอ ความถี่จะลดเอง

## 2026-09-14 — แพลตฟอร์ม บัญชี และพอร์ตเซนต์

ผู้ใช้ต้องการแยกบัญชี EA ออกจากบัญชีเทรดมือเพื่อให้ monitor ได้ชัด — **เห็นด้วยเต็มที่**
และเสนอใช้ MT4 เพราะเข้าใจว่าพอร์ตเซนต์ต้องใช้ MT4

**ตัดสินใจ: MT5 ทั้งคู่ แยกด้วย *บัญชี* ไม่ใช่ *แพลตฟอร์ม***

```
Exness-MT5Real25 / XAUUSDc / $50   →  EA เท่านั้น       (บัญชีเซนต์)
FBS-Real 28642802 / XAUUSD         →  ผู้ใช้เทรดมือ
```

เหตุผลที่ไม่ใช้ MT4:

1. **MT4 backtest ใช้สเปรดคงที่ค่าเดียว** — สเปรดเป็นข้อจำกัดหลักของดีไซน์ ผลจะเชื่อไม่ได้
   MT5 ใช้สเปรดจริงที่บันทึกในอดีต
2. **MT4 ไม่มี real tick** — interpolate จากแท่ง M1 จะซ่อนเหตุการณ์แบบ 2026-09-03
   (ราคาทะลุ SL $12 ใน 7 วินาที) ซึ่งคือความเสี่ยงที่ต้องวัดให้ได้
3. MT4 หยุดพัฒนาแล้ว / tester single-thread / MQL4 คนละภาษา
4. **พอร์ตเซนต์ไม่ได้ผูกกับ MT4** — Exness เปิดบน MT5 ได้ ยืนยันแล้วจากบัญชีจริง

**สถานะ:** ผู้ใช้เปิดบัญชีเซนต์ Exness บน MT5 แล้ว ไม่ต้องติดตั้ง MT4

## 2026-09-14 — พอร์ตเซนต์เป็นข้อบังคับ ไม่ใช่ทางเลือก

ที่ทุน $50 การใช้พอร์ตเซนต์ไม่ได้เป็นเรื่องความชอบ แต่เป็นคณิตศาสตร์:

| | contract size | SL $8 ที่ min lot 0.01 | % ของพอร์ต $50 |
|---|---|---|---|
| บัญชีปกติ | 100 oz | $8.00 | **16%** 💀 |
| **บัญชีเซนต์** | **1 oz** | $0.08 | **0.16%** ✓ |

บัญชีปกติลงไม้เล็กกว่า min lot ไม่ได้ → ต้องมีทุน ~$800 ถึงจะเสี่ยง 1% ได้ที่ SL $8
บัญชีเซนต์คุมความเสี่ยง 1% ได้สบายที่ $50 (ดูตารางใน `reference/XAUUSDc-exness-spec.md`)

**ความคาดหวังที่ตั้งไว้ร่วมกัน:** $50 คือเงินสำหรับ *พิสูจน์ระบบ* ไม่ใช่ *ทำกำไร*
เสี่ยง 1% = $0.50/ไม้ → เดือนหนึ่งได้ไม่กี่ดอลลาร์ ซึ่งถูกต้องแล้ว
และ forward test จะช้า: 1–3 ไม้/วัน → ครบ 200–300 ไม้ใช้เวลา **4–6 เดือน**

## 2026-09-15 — บทบาทของ AI: นักวิจัย ไม่ใช่คนกดเทรด

ผู้ใช้ถามว่าควรเป็น **(A) AI สร้าง EA → EA เทรด** หรือ **(B) AI หา signal สด ๆ → EA เอาไปเทรด**

**ตัดสินใจ: (A)** — Claude เป็นนักวิจัย/นักพัฒนา EA เป็นกฎตายตัวที่เทรดเอง
ผู้ใช้เห็นด้วย

เหตุผลที่ไม่เอา (B) (LLM ตัดสินใจเข้าไม้สด ๆ ผ่าน API):

1. **Backtest ไม่ได้** — เรียก API ทุกแท่ง M5 ย้อนหลังหลายปีทั้งช้าและแพงเกินจริง และ
   **LLM รู้ราคาในอดีตจากข้อมูลที่ใช้เทรน** → look-ahead bias ฝังอยู่ในตัว แยกออกไม่ได้
   ผลลัพธ์ยังไม่ deterministic อีกด้วย → เหลือแค่ forward test ซึ่งช้า 4–6 เดือนต่อรอบ
2. **ทำให้ปัญหาเดิมของผู้ใช้กลับมา** — ปัญหาคือความไม่สม่ำเสมอ ยาแก้คือระบบที่
   input เดียวกันได้การตัดสินใจเดียวกัน (B) แค่เปลี่ยนความไม่แน่นอนจากอารมณ์คนเป็นของ AI
3. **ค่า API อาจเกินกำไร** — ทุน $50
4. **จุดพังเพิ่ม** — ขัดกับหลัก "ห้ามมี bridge ตอน live"
5. ไม่มีหลักฐานว่า LLM ทำนายราคาทองระยะสั้นได้

### Loop สองชั้น (สำคัญ)

- **Loop ใน (เร็ว):** สมมติฐาน → backtest หลายปี → walk-forward → วิเคราะห์ → แก้
  **การปรับ EA เกิดที่นี่เท่านั้น**
- **Loop นอก (ช้า):** EA เวอร์ชันที่ล็อกแล้วรันบนพอร์ตเซนต์ → เทียบผลจริงกับ backtest
  ใกล้เคียง = รันต่อ / ห่างมาก = หาสาเหตุ (cost model ผิด, บั๊ก)
  **ห้ามจูนพารามิเตอร์ตามผลเทรดจริงล่าสุด** — 1–3 ไม้/วัน สองสัปดาห์คือ noise ล้วน

ผลเทรดจริงใช้ตอบว่า *"backtest เชื่อได้ไหม"* ไม่ได้ใช้ตอบว่า *"ควรแก้พารามิเตอร์ตัวไหน"*

### ทางเลือกในอนาคต (ยังไม่ทำ)

ML model ที่เทรนแล้ว **ล็อกและฝังใน EA ผ่าน ONNX** (เช่น meta-labeling กรอง setup SMC)
ยอมรับได้เพราะ deterministic + backtest ได้ + ไม่ต้องใช้ API/bridge
**เงื่อนไข:** ทำหลังจาก EA แบบกฎพิสูจน์ว่ามี edge แล้วเท่านั้น

## 2026-09-15 — News filter: ปิดไม้ก่อนข่าว

ผู้ใช้ตั้งใจจะ **ปิด EA ด้วยมือช่วงข่าว 19:30** — เห็นด้วยกับเป้าหมาย (ANALYSIS-002: SL ทะลุ $12)
แต่ **ตัดสินใจทำเป็นกฎใน EA แทนการปิดมือ** เพราะ:

1. 8:30 ET = 19:30 ไทยเฉพาะช่วง US DST — ฤดูหนาว (หลัง 1 พ.ย. 2026) คือ 20:30
2. ข่าวแรงไม่ได้มีแค่ 19:30 (ISM ~21:00, FOMC ~01:00 ไทย)
3. กฎที่อยู่ในหัวคนไม่อยู่ใน backtest → เทียบผลจริงกับ backtest ไม่ได้
4. ปิด EA ไม่ได้ปิดไม้ที่ถืออยู่ + การแตะ EA ด้วยมือคือโหมดพังอันดับหนึ่ง

**ผู้ใช้เลือก (ก): ปิดไม้ก่อนข่าวทุกครั้ง** (ทางเลือกอื่น: ถือต่อด้วย SL เดิม / ให้ backtest ตัดสิน)

### กฎ

- ข่าว **USD ระดับ High** ที่มีเวลาแน่นอน จาก MT5 Economic Calendar
- ช่วงห้าม = `[ข่าว − 30 นาที, ข่าว + 30 นาที)` เทียบกับเวลาเริ่มแท่ง
- ในช่วงนี้ **ห้ามเปิดไม้ใหม่** และ **ไม้ที่ถืออยู่ปิดที่ราคาเปิดของแท่งแรกในช่วง** (market)
- 30/30 เป็นค่าคงที่จากเหตุผล (สเปรดเริ่มกางก่อนข่าว / ความผันผวนหลังข่าวยังสูง)
  **ไม่ใช่พารามิเตอร์ให้ optimize** — ถ้าจะเปลี่ยนต้องบันทึกเหตุผลและนับเป็น trial
- ค่าอยู่ใน `config/news_filter.json`

### แหล่งข้อมูล

- **live:** EA อ่าน Calendar API เอง ผู้ใช้ไม่ต้องปิด/เปิด EA
- **backtest:** ใช้ไฟล์จาก `ExportCalendar.mq5` (Strategy Tester ของ MT5 อ่านปฏิทินไม่ได้)

### ข้อจำกัดที่รู้อยู่

- ข่าวแบบทั้งวัน/ยังไม่กำหนดเวลา ถูกตัดทิ้ง ไม่ได้กัน
- เหตุการณ์นอกปฏิทิน (สุนทรพจน์ฉุกเฉิน, ข่าวภูมิรัฐศาสตร์) กันไม่ได้
- **ยังไม่ยืนยัน** ว่าเวลาย้อนหลังในปฏิทินแปลง DST ถูกต้องทั้งปี → ต้องเทียบเวลา NFP ในปฏิทิน
  กับแท่ง M1 ที่ราคากระชากจริง ทั้งช่วงฤดูร้อนและฤดูหนาว เมื่อได้ข้อมูล

- **ตัด FVG ออก** (เดิมอยู่ลำดับ 3 ในตารางองค์ประกอบ SMC)
- **Order block กลายเป็นกลไกเข้าไม้หลัก** — แต่เป็นองค์ประกอบที่เคยจัดว่ากำกวมที่สุด (ลำดับ 5)
  → ต้องนิยามให้แคบและเป็นตัวเลขชัดที่สุดก่อนเขียนโค้ด ไม่งั้นพารามิเตอร์จะบวมเกินงบ < 10 ตัว
- **การรอย่อ = limit order** ไม่ใช่ market → engine ต้องรองรับคำสั่งรอเข้าที่ราคา มีวันหมดอายุ
  และยกเลิกเมื่อโครงสร้างเสียก่อนราคามาถึง
- ผลดีโดยตรงต่อปัญหาของผู้ใช้: ถ้าราคาไม่ย่อกลับมา = ไม่มีไม้ → ตัดพฤติกรรม "ตกรถแล้วไล่ราคา" โดยโครงสร้าง
- Candidate เดิม *"sweep + CHoCH + เข้าตอนแท่ง CHoCH ปิดหรือที่ FVG"* ปรับเป็น
  *"sweep + CHoCH (ปิดทะลุ) + รอย่อเข้า order block"*

### ยังต้องถาม

- นิยาม swing high/low และ liquidity ที่ดู
- นิยาม order block / demand-supply zone: แท่งไหน, ขอบเขตโซนใช้ทั้งแท่งหรือแค่ตัวเทียน
- เข้าที่ขอบโซนหรือกลางโซน / SL วางตรงไหน / TP ใช้อะไร
- โซนหนึ่งใช้ได้กี่ครั้ง และรอย่อนานแค่ไหนก่อนยกเลิก

### เกณฑ์ผ่านขั้น dev — ล็อกไว้ **ก่อน** เห็นผลบนข้อมูล Dukascopy

กลยุทธ์จะผ่านขั้น dev ได้ต้องครบ **ทุกข้อ** (ข้อมูล dev 2017 → 2026-04-30):

2. **expectancy > 0R หลังหักต้นทุน**
3. **ชนะการเข้าไม้สุ่มที่คงรูปทรงไม้** — สัดส่วนรอบสุ่มที่ทำได้ดีกว่าหรือเท่า ≤ 5% (จาก 50 รอบ)

   และไม่มีปีเดียวที่ทำกำไรเกิน 50% ของกำไรรวม
5. **max drawdown ≤ 25%** ที่ความเสี่ยง 1%/ไม้

ผ่านขั้น dev แล้วจึงเปิด holdout (ครั้งเดียว): ต้องได้ expectancy > 0R และไม่ต่ำกว่า median ของรอบสุ่ม
