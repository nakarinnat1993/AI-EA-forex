# ANALYSIS-002 — หา Broker Server Timezone จากข้อมูลเทรด

**วันที่:** 2026-09-10
**วิธี:** ผู้ใช้เสนอให้ใช้ event ที่รู้เวลาแน่นอน (ข่าวแรง) มา calibrate — เป็นวิธีที่ถูกต้อง
**สคริปต์:** `research/detect_server_tz.py`

---

## หลักการ

หา **SL blowthrough** = ไม้ที่ปิดเลยราคา SL ไปมาก แปลว่าราคาวิ่งเร็วจน SL ไม่ทำงานตามที่ตั้ง
ซึ่งเป็นลายเซ็นของ news spike จากนั้นเทียบเวลา server กับเวลาข่าวที่รู้ว่าเป็น GMT อะไร

พบ SL blowthrough > $1 ทั้งหมด **25 เหตุการณ์** จาก 3,460 ไม้

---

## ผลลัพธ์: ยืนยัน GMT+3 ในช่วง US DST

เหตุการณ์ที่ทะลุ SL หนักที่สุด 3 อันดับแรก เกิดที่ **15:30:0x server ทั้งหมด**
(ภายใน 8 วินาทีจาก 15:30:00 — เป็นการประกาศตัวเลขตามกำหนดแน่นอน):

| วันที่ | เวลา server | ทะลุ SL | P&L |
|---|---|---|---|
| 2026-09-03 (พฤ) | **15:30:07** | $12.06 | -$15.08 |
| 2026-08-12 (พ) | **15:30:08** | $9.44 | -$13.04 |
| 2026-04-10 (ศ) | **15:30:01** | $8.08 | -$7.76 |

US data release มาตรฐานคือ 8:30 AM ET ซึ่งในช่วง EDT = **12:30 GMT** (= 19:30 เวลาไทย
ตรงกับที่ผู้ใช้ระบุ)

**12:30 GMT → 15:30 server ⟹ server = GMT+3** ✓ ยืนยันจาก 3 เหตุการณ์อิสระ

### หลักฐานสนับสนุน

ชั่วโมงที่ผู้ใช้เทรดหนักสุดคือ server 14–17 → เวลาไทย 18:00–21:00 (ตอนเย็นหลังเลิกงาน)
และช่วงเทรดทั้งหมด server 01–20 → ไทย 05:00–24:00 สอดคล้องกับคนที่ตื่น 5 โมงเช้าถึงเที่ยงคืน

## ⚠️ ยังไม่ยืนยัน: พฤติกรรมช่วงฤดูหนาว (DST off)

ข้อมูลฤดูหนาว (พ.ย. 2025 – ก.พ. 2026) **ไม่มีเหตุการณ์ blowthrough ที่ชัดพอ**
ในช่วงเวลาที่ US ปล่อยข่าว — ไม้ที่ขาดทุนหนักกระจายทั้ง 15:30 และ 16:30 สรุปไม่ได้

**สมมติฐานที่น่าจะเป็นที่สุด (ยังไม่พิสูจน์):** server ตาม US DST คือ
**GMT+2 ฤดูหนาว / GMT+3 ฤดูร้อน**

เหตุผล: เป็นแบบที่โบรก MT5 ส่วนใหญ่ใช้ เพื่อให้แท่ง Daily ปิดที่ 17:00 New York ตลอดปี
(00:00 server = 17:00 ET เสมอ) ภายใต้แบบนี้ 8:30 ET จะตรงกับ 15:30 server ทั้งปี

**ผลกระทบถ้าเดาผิด:** Asian range, London open, session filter จะเพี้ยนไป 1 ชั่วโมง
ตลอดครึ่งปี — ทำให้ backtest ผิดทั้งหมด

### วิธียืนยันให้จบ (เลือกทางใดทางหนึ่ง)

1. **ทำเองได้ทันที** — เปิดกราฟ XAUUSD M5 ใน MT5 เลื่อนไปวัน NFP ฤดูหนาว
   (2026-01-02, 2026-02-06 หรือ 2026-03-06) หาแท่งที่พุ่งแรงที่สุดแล้วอ่านเวลา
   - ถ้าเป็น **15:30** → server ตาม US DST (GMT+2 หนาว / GMT+3 ร้อน)
   - ถ้าเป็น **16:30** → server เป็น GMT+3 คงที่ทั้งปี
2. **รอ Phase 1** — เมื่อโหลดข้อมูล M5 ย้อนหลังมาแล้ว ตรวจ spike ในเดือนฤดูหนาว
   จากแท่งราคาโดยตรงได้เลย (แม่นกว่า ไม่ต้องพึ่งไม้ที่ผู้ใช้บังเอิญเปิดไว้)

**ไม่เป็น blocker** — Phase 1 (โหลดข้อมูล + เขียน backtester) เริ่มได้เลย
แต่ต้องยืนยันก่อนเขียน logic ที่อิง session

## ผลพลอยได้ 1: EA ต้องมี news filter (บังคับ)

ในเหตุการณ์ 2026-09-03 **SL ตั้งไว้ 4451.86 แต่ปิดจริงที่ 4463.92 — ทะลุไป $12**

แปลว่า **SL ไม่ได้ให้การป้องกันเลยในช่วงข่าว** ความเสี่ยงจริงของไม้นั้นคือ 5 เท่าของที่ตั้งใจ

→ ข้อกำหนดของ EA: **ห้ามเปิดไม้ใหม่ก่อน/หลังข่าวแรงตามกำหนด และพิจารณาปิดไม้ที่ถืออยู่
ก่อนข่าว** ต้องมีปฏิทินข่าว (ForexFactory) หรืออย่างน้อย hard-code ช่วง 15:30 server
